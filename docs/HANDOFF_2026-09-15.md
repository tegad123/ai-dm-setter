## 4. The architecture you must understand before changing anything

### 4.1 Two position-keepers, one of them authoritative

There are **two** systems tracking where a conversation is in the script:

1. **Legacy** — `computeSystemStage` in `src/lib/script-state-recovery.ts`,
   a history-rescan cascade. **This one owns `currentScriptStep` and actually
   persists.**
2. **Compiled FSM** — `src/lib/script-fsm/*`, a real state machine compiled from
   the script at upload. **Currently SHADOW-ONLY.** It logs its answer next to
   legacy's in `RoutingShadowLog` but does not drive behaviour unless
   `FIX_D_ROUTING_AUTHORITATIVE` names the account.

**Consequence that has bitten repeatedly:** fixing something in the FSM alone
changes nothing in production. If a position bug must be fixed now, it has to be
fixed in the legacy path too. See the no-signal fix in §6 for the pattern.

### 4.2 The NULL-branch failure family

This is the single most important thing in the codebase.

When branch selection returns **null**, the "required messages" set widens from
the *selected branch* to the **whole step**. The deterministic injectors then ship
**other branches' copy**. Every one of these was the same root cause:

- Discord link sent to a lead who said no (the YES branch's link on a decline)
- "you make it into the discord?" to a lead who never joined
- Step 2's "love to see it" landing on an unreadable image

Branch selection now resolves via, in order: a locked judge result → judge and FSM
**agreeing** → the judge abstaining while the FSM has a **structural** pick
(`default`/`source`/`always`/`data`). A judge label that *disagrees* with the FSM
adopts nothing. See `src/lib/ai-engine.ts` around the `[script-fsm] branch ...
adopted` log line, and `tests/unit/branch-agreement.test.ts`.

**When you see wrong-branch copy in a conversation, suspect a null branch first.**

### 4.3 The egress gate

All AI sends funnel through `shadowEgressCheck` → `canSend` at the physical Meta
send (`src/lib/instagram.ts sendDM`, `src/lib/facebook.ts sendMessage`).
Guards live in `src/lib/state-machine/egress-guards.ts`:

- `wait_boundary` — blocks script copy that sits after a `wait_for_response`
  from shipping before the lead has replied
- `verbatim_repeat` — blocks a bubble that repeats already-delivered content

`FIX_D_CANSEND_AUTHORITATIVE` is a **per-platform** csv. Currently `FACEBOOK`.
Instagram is shadow-only until the go-live flip.

### 4.4 Generate-only vs away mode — the trap

```
computeInboundAiActive = (awayMode || generateOnly) && defaultAiActive
shouldAutoSendReply    = aiActive && (awayMode || autoSendOverride)
```

**Turning generate-only OFF while away mode is OFF produces silence, not go-live.**
New leads get `aiActive: false`. Go-live is two settings in this order:
**away mode ON, then generate-only OFF.** The dashboard switch does both
correctly; the CLI scripts do not (they warn).

```bash
npx prisma migrate deploy                      # local DB catches up
npx tsx scripts/clone-script-to-local.ts cmu270hla0001js047btcczo6   # client script → local, activated
npx tsx scripts/reset-local-test.ts            # truncate leads/convs/messages
DISABLE_META_BACKFILL=true META_SEND_DRY_RUN=true \
  FIX_D_CANSEND_AUTHORITATIVE=FACEBOOK,INSTAGRAM pnpm exec next dev -p 3005

./scripts/drive-local-flow.sh 9100000000000001 "brand new to trading" "Houston" "..."
./scripts/run-v2-flows.sh                      # all six of Tega's runs
```

Two knobs that matter, both dev-only and NODE_ENV-guarded:

- `DISABLE_META_BACKFILL=true` — without it the processor imports the **real**
  Messenger thread for that PSID and the engine sees a months-old conversation
  instead of a cold lead.
- `META_SEND_DRY_RUN=true` — gate and guards run for real; only the Meta HTTP call
  is skipped. Needed because a simulated inbound does not open a 24h Messenger
  window, so real sends fail with Meta error #10 and the flow cannot progress.

`SETTLE_S` (default 25) is the silence after the last bubble before a turn is
considered finished. Too short and the next message aborts the drip mid-group.
**Flows must run sequentially.**

### The bugs, and why they happened

1. **Step-1 misroutes (Tega's 28).** Step-1 routing decided on *lead origin*
   (ManyChat vs direct DM). v2 decides on *message content*. Every inbound lead
   fell into "Cold inbound" and got the cold greeting. Source routing now applies
   only when the script's first step actually names ManyChat/flow origin —
   `stepIsSourceRouted` in `src/lib/script-fsm/compiler.ts`, shared with
   `selectStep1BranchesForPrompt`. **COMPILER_VERSION is now 3.**

2. **Re-asking an answered question (Tega's "92").** The branch classifier only
   ran on steps carrying a `runtime_judgment` action; v2 step 2 has none, so it
   was never consulted → null branch → improvised re-ask. Now classifies when the
   step has a judgment action **OR** forks. Also: it only ever saw the *latest*
   lead message, so "brand new to trading" then "Houston" lost the first fact —
   it now sees the last three.

3. **Raw JSON to the lead.** v2's Solicitation branch says "send nothing"; the
   model returned an empty message and the parser fell back to printing the whole
   payload as four bubbles (code fence, `"format"`, `"message"`, `"stage"`).
   Fixed in `parseAIResponse`. Then on re-run the model *invented* "gimme a sec
   bro, looking into this" — so **N1c** now suppresses any output on a branch
   whose only actions are `runtime_judgment`.

4. **The decline bug (Tega: "best catch of the night").** Lead says no → gets the
   Discord link anyway, then gets told they joined. Null branch → whole-step
   injection. Fixed by scoping N1 (link) and N1b (messages) to the selected branch.

5. **Distress missed.** On Sept 13 the classifier hit a transient credential
   error, the fallback is regex-only and saw no self-harm language, so a lead
   who wrote "lost all my capital... my mom is old" got the cold greeting
   (conv `cmu02ja3i000hl904j3eisq94`). The classifier calls that text
   `severe_hardship` correctly when it runs. Now retries on **every** transient
   failure, not just timeout/parse.

6. **No-signal credit.** An unreadable image credited the step-1 ask and advanced
   to step 2, so step 2's copy shipped on it. `isAnswerableReply` in
   `script-fsm/runtime.ts` + the same rule applied to the **legacy** cursor in
   `script-state-recovery.ts` (see §4.1 — FSM-only would have done nothing).
   Terse real answers ("NY", "2y", "no") and non-latin answers still credit.
